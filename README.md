# AR Collections Dashboard

An accounts-receivable and collections dashboard for a seaplane and aviation operator in the Maldives. It shows where the money is, how old it is, and who to call first.

**Live demo:** https://amila-nandasiri.github.io/ar-collections-dashboard/

> Built on **fictional data**: 100 customers and 18 months of invoices generated by a script. No real company or customer information is used.

## Why I built it

Collections work is usually done from an aged-debtors report in Excel. I improved Days Sales Outstanding by 13% in my current role through tighter credit control, and this project turns that experience into a tool: the analysis a finance team needs at month-end, calculated automatically and ranked into a worklist.

## What it shows

- **Headline KPIs:** total receivables, overdue balance, DSO, Collection Effectiveness Index (CEI), cash collected, and customers over their credit limit
- **Aging:** balance by days past due (not yet due, 1–30, 31–60, 61–90, 90+)
- **DSO trend:** month-end DSO over the last 16 months
- **Billed vs collected:** monthly, showing the December–April high season
- **Receivables by segment:** resorts, tour operators, hotels, corporates and liveaboards
- **Collections worklist:** every customer ranked by priority with a suggested next action (escalate, resolve dispute, hold credit, call, remind). Filter by segment or account manager, and select a customer to see its open invoices.

## How the numbers work

| Measure | Formula |
|---|---|
| **DSO** | Month-end receivables ÷ billing in the last three months × 91 days |
| **CEI** | (Opening AR + billing − closing AR) ÷ (opening AR + billing − closing current AR) × 100 |
| **Priority score** | Overdue balance weighted by age (1× for 1–30 days up to 4× for 90+), × risk-rating factor (A 0.9 to D 1.3), × 1.25 if over the credit limit |
| **Priority tier** | Top 20% of scores are High, the next 30% Medium, the rest Low |

The month-end balances behind DSO and CEI are rebuilt from the invoice and payment history, so each past month reflects what was actually open on that date.

## Tech

- **Data:** Python (standard library), in [`scripts/generate_data.py`](scripts/generate_data.py). See [`data/README.md`](data/README.md) for the data dictionary.
- **App:** React, TypeScript, Recharts and Tailwind CSS, built with Vite. All calculations run in the browser, in [`src/lib/ar.ts`](src/lib/ar.ts).
- **Hosting:** GitHub Pages, deployed by GitHub Actions on every push to `main`

## Run it locally

```bash
npm install
npm run dev        # start the dashboard at http://localhost:5173
npm run data       # regenerate the sample data (needs Python 3)
```
